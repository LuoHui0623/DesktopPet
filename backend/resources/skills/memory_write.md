# 记忆写入

> 把主人值得长期记住的信息写进结构化记忆。主人明确提出「记住」「记一下」，说出会持续成立的偏好、习惯、约定或重要安排，或纠正了以前记下的同类信息时，使用本技能。一次性、临时的信息不写入。

## 执行流程

1. **判断信息类型**：确认主人表达的是长期有效的信息（偏好、习惯、约定、安排、纠正），而非一次性内容。
2. **先看清现状**：调用 `index`（`resource` 取 `structured`）查看条目数量、分区（tags）与启用/弃用统计；再用 `read`（`resource` 取 `structured`）按分区读出条目。每行形如 `[#12] 喜欢美式（饮品）`，`#12` 是条目 id，括号里是第一个之外的 tag；`[已弃用]` 标记暂停使用的条目。
3. **写入**（只用 `memory` 工具，不再用 `edit` 改 structured）：
   - 新信息：`{"action": "add", "content": "喜欢美式", "tags": ["饮品", "咖啡"], "priority": 2}`。`content` 写一个可归类的短语或值，不写完整句式；`tags` 平铺，第一个是分区，其余是细分；`priority` 默认 2。
   - 相同内容且 tag 有交集时不会新增，只刷新确认时间，工具返回 `reused: true`。
   - 纠正旧信息：先看清旧条目 id，`{"action": "disable", "entry_id": 12, "reason": "改喝燕麦拿铁"}` 弃用旧条目，再 `add` 新内容。不要尝试原地修改。
   - 恢复弃用条目：`{"action": "enable", "entry_id": 12}`。
4. **复用 tag**：优先使用 `index` 里已列出的 tag。归一化后（去空格、忽略大小写）命中已有写法会沿用原拼写；确实需要新分区或细分类时才新建，工具会返回 `new_tags` 并留下告警。
5. **告知结果**：完成后用一句话告知主人记住了什么。

## 约束

- 不要记录主人没有表达的内容。
- 没有 `update` 与 `merge`：改值一律「弃旧 + 新增」；合并 tag 只由设置页人工执行，不要尝试。
- 条目立即写入，不经过草稿审批；写入结果以工具返回的 `entry.id` 为准。
- 敏感信息（密码、身份证号等）拒绝写入。

## 输出

`output` 写一句给主人看的结论，例如「记住了你更喜欢美式咖啡」。
