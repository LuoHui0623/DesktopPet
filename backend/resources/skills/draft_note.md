# 自记笔记

> 在草稿本上写下宠物自己的便签：临时计划、待办、要追问或提醒主人的事。主人让你「记一下」「别忘了」但属于短期安排时，或你自己需要把待办写下来免得忘掉时，使用本技能。长期的偏好与事实用「记忆写入」。

## 执行流程

1. **先看现状**：调用 `index`（`target` 取 `FILES`）确认文件域可用动作，再用 `read`（`resource` 取 `draft`）读出全文与行号。草稿本初始只有一行标题。
2. **想清楚写什么**：一条一行，写清「做什么 / 什么时候 / 还缺什么信息」，不写寒暄和情绪描述。
3. **提出写入**：写入动作各自是独立工具，动作名就是工具名（`resource` 固定取 `draft`）：
   - `append`：`{"content": "..."}` 把内容加到末尾，多条一次写完。
   - `insert`：`{"line": 3, "content": "..."}` 在指定行之前插入，`line` 取 1 到 行数+1。
   - `replace_lines`：`{"line_ranges": [[5, 5]], "content": "..."}` 整段替换指定行；`expect` 填这些行的原文可防止改错。
   - `replace_regex`：`{"line_ranges": [[3, 8]], "pattern": "旧", "content": "新"}` 只在给定行范围内做正则替换；行范围必填。
   - `delete_lines`：`{"line_ranges": [[5, 5]]}` 删除指定行；草稿本没有删除文件本体的权限。
   - 回执「已提出，尚未写入文件……等待 review 批准」表示条目已入队；主人逐条批准后才落盘，不要重复提交同一动作。
4. **处理回执**：如果收到带 `settlement` 的“被拒绝”或“未提交”回执，条目已经作废；先重新 `read` 核对当前内容，再提出修改，不要假定已经写入。回执写明“检测到哈希不一致”时，只说明磁盘版本与读取基准不同；若同时写着“不再自动合并旧基底”，剩余条目已按当前版本重新定位后提交，不要假定旧内容还在原来的行上。
5. **告知结果**：一句话说明记下了什么，不复述整份草稿；尚未确认时说明“待确认后写入”。

## 约束

- 只写 `draft` 资源，不动小世界的其他文件和表情包。
- 草稿本是短期便签，不是长期记忆：跨天依然成立的偏好、约定用「记忆写入」。
- 敏感信息（密码、身份证号等）拒绝写入。
- 行号以工具返回的结果为准；报「行号超出范围」「expect 不匹配」时先重新 `read` 核对，不要盲改。

## 输出

执行结束后，`output` 写一句给主人看的结论，例如「已经把『周五问主人要不要续费』记到草稿本，待确认后写入」；若工具返回已提交，则直接说已写入。
