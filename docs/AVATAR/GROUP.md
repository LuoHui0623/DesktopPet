# 形象组与人设挂载

> 职责：定义形象组、人设 id 的归属方式、组内包的启用规则、目录与接口变化。
> 依赖：`PersonaService` 的当前人设、`module/avatar` 的包扫描与启用项、前端 `avatar.service.ts` 与设置页。
> 不回答：人设内容与切换语义、状态注册、动画解码、窗口命中与穿透。
> 状态：已实现。

## 为什么要分组

如果形象包平铺在 `data/avatars/<pack_id>/`，全局只有一个 `avatar.active`，会带来两个问题：

- 不同人设无法拥有各自的形象集合；切换人设后形象不会跟着换。
- 包里混放不同角色的资源时，目录与设置页无法表达“哪些包属于谁”。

形象组把“人设”与“形象资源”绑定，让目录、启用项与设置页都按人设收敛。

## 定义

- **形象组（AvatarGroup）**：一个人设 id 对应的形象目录，内含一个或多个形象包。组目录名就是人设 id。
- **组内包（AvatarPack）**：组目录下的一个形象包，仍使用原有 `manifest.json`、静默主形象与状态动画契约。
- **当前人设（active persona）**：`PersonaService.active_id()` 的返回值；形象域只读取，不修改人设。
- **当前形象**：当前人设的组内被选中的包；按人设分别记忆。
- **组默认包**：包 id 为 `default` 的包；不存在时取组内按目录名排序的第一个包。

一个形象组只属于一个人设；本轮不支持跨人设共享组，也不支持一个人设挂多个组。

## 目录与归属

```text
data/avatars/<persona_id>/
├─ default/
│  ├─ manifest.json
│  ├─ static.png
│  └─ <状态资源>
└─ <其它 pack_id>/
   └─ ...
```

- `persona_id` 来自人设卡片文件名，允许文字、数字、下划线与连字符，长度 1–32；目录名必须与人设 id 完全一致。
- `pack_id` 沿用包规则：字母、数字、下划线、连字符，长度 1–64。
- 归属由目录决定，不再在 `manifest.json` 或人设 YAML 里重复声明。
- 只有当前人设目录下的包进入目录响应；其它人设的包不可见、不可启用。

内置默认形象放到默认人设目录下：

```text
backend/resources/avatars/芙芙/default/
```

首次启动时，若默认人设目录不存在，把内置包复制到该目录；已存在时不覆盖。

## 当前形象与记忆

读取顺序：

```text
当前人设 → 该人设的组目录 → 记住的包 → 组默认包 → 无包
```

- 每个启用人设分别记忆一个包 id，配置键为 `avatar.active.<persona_id>`。
- 记住的包不存在或校验失败时，回退组默认包，并更新记忆。
- 组默认包也不存在（组为空或全部包不可用）时，当前形象为空，悬浮窗显示占位。
- 首次进入某个人设且没有记忆时，直接使用组默认包。
- 切换人设后，悬浮窗重新读取目录并按上述顺序选择形象；不沿用上一个人设的包。

## 接口变化

### 目录响应

`GET /api/avatars` 增加 `persona`，`active` 允许为 `null`：

```json
{
  "persona": "芙芙",
  "active": "default",
  "preset_states": ["idle", "thinking", "speaking", "executing", "sleeping", "disconnected"],
  "packs": [
    {
      "id": "default",
      "name": "默认形象",
      "active": true,
      "frame": { "width": 240, "height": 240 },
      "fallback": "idle",
      "static": "static.png",
      "states": { "idle": { "frames": ["idle_0.png"], "frame_ms": 160 } }
    }
  ]
}
```

- `persona` 是当前人设 id。
- `packs` 只包含当前人设组内的包；组不存在或全部包不可用时为空数组。
- `active` 是当前包 id；无可用包时为 `null`。
- `preset_states` 与包内字段不变。

### 资源路径

帧图与主形象路径加入人设段：

```text
GET /api/avatars/<persona_id>/<pack_id>/<path>
```

- 路径校验要求 `<persona_id>` 与当前人设一致，`<pack_id>` 属于该人设组，`<path>` 不越出包目录。
- 不再提供不带人设段的资源路径，避免不同人设同名包串资源。

### 启用接口

`PUT /api/avatars/active` 与 `PUT /api/settings/avatar` 的请求体仍是包 id：

```json
{ "id": "default" }
```

- 包必须在当前人设组内，否则返回 404。
- 只写入 `avatar.active.<persona_id>`，不影响其它人设的记忆。
- 返回的目录响应按当前人设重新计算。

## 切换人设

```text
设置页启用人设
  → 后端更新 persona.active
  → 通知悬浮窗“人设已切换”
  → 悬浮窗重新请求 GET /api/avatars
  → 按当前人设的记忆 / 组默认包选择形象
```

- 人设切换成功是形象切换的触发条件；形象域不监听人设文件内容变化。
- 通知只用于让悬浮窗重新拉取目录；形象选择仍以后端返回的 `persona`、`active` 与 `packs` 为准。
- 人设切换失败（人设不可用）时不改变当前形象。

## 缺组与失败

| 情况 | 行为 |
|---|---|
| 当前人设没有形象组目录 | `packs` 为空、`active` 为 `null`；悬浮窗显示占位，整窗可交互 |
| 组目录存在但没有可用包 | 同上，不借用其它人设的包 |
| 记住的包不存在或校验失败 | 回退组默认包 |
| 组默认包也不可用 | 当前形象为空，显示占位 |
| 人设 id 与目录名不一致 | 该目录不进入当前人设组 |
| 切换人设失败 | 保持原人设与原形象 |

缺组时不回退到全局默认组，也不借用 `default` 人设的资源；占位状态下不阻塞窗口交互。

## 设置页

- “形象”tab 只列出当前人设组内的包，并显示当前人设 id。
- 组内无包时显示“当前人设没有可用形象”，不展示其它人设的包。
- 保存后写入当前人设的记忆键，并通知悬浮窗重载。
- 人设 tab 切换成功后，形象 tab 下次打开时重新读取目录；悬浮窗立即重载。

## 迁移与非目标

迁移：

- 内置资源从 `resources/avatars/default/` 移到 `resources/avatars/<默认人设>/default/`。
- 数据目录下的旧平铺包不再识别；需要手工移入对应人设目录。
- 旧的全局 `avatar.active` 不作为任何人设的记忆；当前人设首次选择时使用组默认包。

非目标：

- 不支持一个人设挂多个组，也不支持跨人设共享组。
- 不在 `manifest.json` 或人设 YAML 中声明归属；归属只由目录决定。
- 不在本轮实现组级元数据、组封面或组内排序配置。
- 不改变包内 manifest、状态、动画与命中契约。

## 已确认口径

- 形象组内含多个包，组目录名就是人设 id；一个人设一个组。
- 归属由目录决定：`data/avatars/<persona_id>/<pack_id>/`。
- 切换人设时自动切到该人设的形象组，并按人设记住上次选中的包。
- 当前人设没有可用形象组时显示占位，不借用其它人设的资源。
