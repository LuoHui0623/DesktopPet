# 文件域导航

> 职责：给文件域一个入口——边界在哪、有哪些概念、组件如何分工、任何实现都不得违反哪些事实、按什么顺序读。
> 依赖：本目录五份主题文档与 `Arch.md` 的架构分层。
> 不回答：各主题的契约正文（见对应文档）、任务排期与进度。
> 状态：已实现（契约与实现一致）。

## 定位

文件域负责三件事：**让调用方发现自己能操作什么**（索引）、**读写文件内容**（动作）、**在写入磁盘前保护用户已有内容**（守卫）。

对应的三条边界：

| 做 | 不做 |
| --- | --- |
| 按当前权限投影可发现的目录、条目与动作 | 用索引结果充当权限凭证 |
| 以整文件哈希记录版本、在写入前拦截过期基底 | 承诺拦截本应用之外程序的并发写入 |
| 把写动作拆成可按 hunk 审阅的 range 条目 | 暂存文件全文、按快照回滚、自动三方合并 |

## 概念

| 概念 | 定义 |
| --- | --- |
| `resource_id` | 一级目录的资源标识（如 `world`），索引、读取、写动作共用同一取值 |
| `EditAction` | 一组写动作的**统称**，不是工具、不是权限、不是审批主体 |
| 动作 | 独立命名的具体操作（`append`、`delete_lines`、`create_dir` 等），各自持有权限 |
| 条目 | 队列的原子单元：`{操作, range_lines, 新内容}`；一次动作可展开为多条 |
| 并 action | 同一 hunk（两段间未改动行 ≤ 6）或重叠的已批准条目合并成一条 action，审批与撤回按该 action 计 |
| `H0` / `H1` | 读取版本 / 磁盘当前版本；`H1` 由系统使用，不进入模型上下文 |
| 占用 | 应用内以规范化绝对路径为键的编辑协调，不是跨进程锁 |
| review | 提交前唯一的人工授权点，按 hunk（action）批准或驳回 |

## 组件

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| `Index` | 返回两种视图：领域视图给目录与动作，目录视图给条目与占用状态 | 不读正文、不建立版本基准、不批准操作 |
| `FileGuard` | 占用协调、前置校验、review 与授权、已批准条目队列、提交确认与结果 | 不把文件内容作为暂存草稿，不自行写盘 |
| `FileService` | 读取、计算哈希、模拟动作、计算 diff、执行已批准的修改 | 不替代审批，不写未经批准的内容 |
| `FilePipeline` | 描述 `index → read → 编辑 → review → 提交` 的流程 | 不是实体，不引入同名类 |

## 不变量

以下八条与具体实现无关，任何实现都不得违反。右侧给出违反时的判定方式，便于复核时否决。

| # | 不变量 | 违反的判定 |
| --- | --- | --- |
| 1 | 提交前真实文件不变 | 执行写动作后、提交前比对磁盘哈希，与 `H0` 相同 |
| 2 | 只提交 `approved` | 队列中存在 `proposed` 或 `rejected` 时，其 range 出现在最终文本中 |
| 3 | 清空不等于删除 | 仅有 `delete_lines` 权限时文件本体消失，或回执把空文件表述为已删除 |
| 4 | 非空目录不删 | `delete_dir` 在非空目录上成功，或其删除范围超出该目录自身 |
| 5 | `H1` 不进模型上下文 | 模型侧消息中出现版本 token，或要求模型复述 token |
| 6 | 并 action 只改审批与撤回单元，不改语义 | 合并前后净 diff 不同，或合并改变了未重叠区域的结果 |
| 7 | 未审条目不入提交 | 未经过 review 的条目出现在提交结果中 |
| 8 | 部分成功必须区分 | 一次调用部分条目被拒时，回执宣称整次调用成功 |

## 边界

**权限边界。** 探索不扩大权限：索引只列当前任务可用的动作，`action_permissions` 恒为对应 `type` 动作集的子集。删除内容与删除本体是两项权限（`delete_lines` / `delete_file`），不可互相替代。目录动作不递归。

**并发边界。** 锁只协调本应用内的任务；外部程序仍可在校验之后、写入之前修改文件。多文件提交不宣称原子性，逐文件报告结果。已知限制必须写进回执，不声称已避免覆盖。

**兼容边界。** `index` 输出一次性替换：不保留旧键并行、不设过渡期、不加兼容开关。动作集不保留 `edit` 聚合入口。

## 依赖与落点

| 层级 | 位置 | 状态 |
| --- | --- | --- |
| 工具层 | `backend/module/agent/tools/files.py` | 每个动作一个工具；无 `edit` 聚合入口 |
| 常量与登记 | `backend/constants/files.py` | `RESOURCES` 登记、领域保留字与动作分组 |
| 权限 | `backend/module/files/permissions.py` | 按任务权限快照投影动作 |
| 服务 | `backend/module/files/service.py` | 索引、读取、检索与写动作入队；不落盘、不审批 |
| 处理器与视图 | `backend/module/files/handlers.py`、`views.py`、`catalog.py` | 虚拟资源读取、索引序列化与条目投影 |
| 队列与会话 | `backend/module/files/ranges.py`、`session.py` | 条目状态机、并 action、`H0` 只读副本 |
| 守卫与版本 | `backend/module/files/guard.py` | 占用、等待取消、全文哈希与分区处置 |
| 提交 | `backend/module/files/commit.py` | 唯一落盘入口；逐文件提交，不自动合并 |
| 结算 | `backend/module/agent/review.py` | 复核、按 hunk 授权、逐文件回执 |
| 消费方 | `backend/tests/service/test_files_*.py`、`backend/tests/acceptance/test_files_end_to_end.py` | 契约断言与端到端不变量 |

## 非目标

- 不实体化 `FilePipeline`，不把流程抽象成可替换组件。
- 不把 `Index` 当作权限凭证或文件正文来源。
- 不为 `memory` 等其它域预留审批复用路径。
- 不在本域文档记录任务编号与排期。
