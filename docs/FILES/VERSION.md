# 文件域版本与一致性契约

> 职责：定义「什么算同一版本」「编辑期以什么为计算基底」「版本变了如何分区处置」「锁协调到什么范围」。
> 依赖：[QUEUE.md](QUEUE.md)（条目与 range）、`backend/module/files/service.py`、`backend/module/files/token.py`。
> 不回答：条目的合并与 review 呈现（见 [QUEUE.md](QUEUE.md)）、动作参数（见 [ACTIONS.md](ACTIONS.md)）。
> 状态：已实现（契约与实现一致）。

## 版本

一个文件的版本是该文件**归一化后的全文 SHA-256**：

```text
读取完整文件 → decode("utf-8-sig") 去 BOM
             → "\r\n" 与 "\r" 统一为 "\n"
             → text.encode("utf-8")
             → SHA-256
```

- BOM 差异与 CRLF 差异归一后视为**同一版本**，不构成冲突。
- 其余文本差异（行尾空格、缩进、Unicode 组合形式、行内容本身）**均构成新版本**。
- 路径、任务身份、目标身份是独立的绑定字段，**不混入** Content-Hash。
- 部分行读取（`read` 带 `line_ranges`）仍对**当次读到的整个文件**计算哈希。
- 解码失败即明确报错，不用替换字符静默降级。

## 两个 token

| 名称 | 含义 | 可见性 |
| --- | --- | --- |
| `H0` | `read` 时确立的读取版本，是条目的位置锚点与计算基底 | 服务端会话持有 |
| `H1` | 校验时发现的磁盘当前版本 | 系统使用，**不进入模型上下文** |

`H1` 由系统传递与使用，模型不可见；模型不得被要求复述版本 token。暂存条目本身仍作为上下文提供给模型。

## 只读副本的边界

编辑会话持有一份 `H0` 的**只读文本副本**作为稳定计算来源。它的身份边界必须严格：

| 是 | 不是 |
| --- | --- |
| 进程内、任务级 | 跨进程或跨任务共享 |
| 只用于按 `H0` 计算 range、合并与 diff | 用于断定磁盘未变 |
| 校验通过后按路径 + 摘要复用 | 暂存草稿、文件快照、可回滚备份 |
| 校验失败即丢弃、按 `H1` 重建 | 落盘文件 |

**每次编辑前校验的是磁盘实际内容，不是副本。** 副本只解决「按哪个版本算」，不解决「磁盘现在是什么」。

## 校验时机

- 每次 `EditAction` 发起时校验一次（前置校验链的一环）。
- 每次提交前再校验一次。
- 校验不一致即停止该动作，不沿用当前基底继续。

应用内锁不约束外部程序：外部程序仍可能在「校验之后、写入之前」修改文件。提交前哈希只能发现检查时刻之前的改动，不能保证此后的改动；原子替换也不能消除该竞态。此限制已被接受，回执只声明「检测到哈希不一致」，不宣称避免了覆盖。

## 外部变更的分区处置

磁盘变为 `H1` 时，计算 `H0 → H1` 的 `diff_lines`——由同一归一化文本**逐行比较**得出，不使用原始字节 diff——再与队列中各 action 的 `range_lines` 逐一求交。

```text
版本 H0、已批准条目 [A, B]
    ↓ 外部修改，编辑或提交前检查失败
停止操作；重新 read 当前文件并提示外部改动
    ↓
当前版本 H1 由系统使用，不进入模型上下文；计算 H0 → H1 的 diff_lines
    ↓
相交的条目作废 → 基于 H1 重新提出 → 预览 → review → 入队
不相交的条目按行号偏移映射到 H1 → 保留原批准，继续参与预览与提交
```

- **相交即作废**：`range_lines` 与 `diff_lines` 有交集的条目失效，须由编辑者基于 `H1` 重新提出、重新 review。
- **不相交即保留**：按行号偏移映射到 `H1` 后**保留原批准**，继续有效。
- **不标注已偏移**：偏移是内部行号映射，不构成语义变化，标注只会增加 review 噪音。
- 偏移只改位置，不改条目内容与期望新内容。

旧条目不得自动应用到新版本；编辑者若仍需要原意，应结合新内容重新提出。未相交的条目不是「旧条目」，其批准继续有效。

## 锁

| 项 | 口径 |
| --- | --- |
| 范围 | 仅协调本应用内的任务 |
| 键 | `Path.resolve()` 后的绝对路径 |
| 值 | 持有者 `task_id`，仅用于可重入判定与 `editing_by` 展示 |
| 取得时机 | 首个编辑行为时（先占后审）；`read` 不占 |
| 重入 | 同一任务对同一文件重入视为已持有，不排队 |
| 对读取 | 有权限的读取不被编辑锁阻塞 |
| 释放 | 提交、取消或任务结束时释放，不设例外 |

键必须是规范化绝对路径：`..`、相对路径、符号链接指向同一实际文件时只能产生一把锁，否则同一文件会出现两把互不相知的锁。

取得顺序固定为：

```text
检查占用 → 取占用 → 权限校验 → 版本校验 → 计算 range/diff → review 授权
```

其中**没有预先人工审批**；人工授权只在 review 一处发生。等待可被取消。

## 读取可见性

| 读取者 | 看到的版本 | 看到的在途条目 |
| --- | --- | --- |
| 编辑者本人（版本仍为 `H0`） | `H0` 对应原文 | 自己的暂存条目 |
| 编辑者本人（已变 `H1`） | 当前原文 + 外部改动提示 | 旧条目作参考，不自动参与 |
| 其他任务 | 磁盘当前原文，附 `H1` | **不展示他人在途行为** |

`read` 不把预期效果伪装成磁盘内容。目录视图的 `editing_status` 是观察值，不是锁凭据，操作时必须重新检查；占用者自身看到的提示不应声称自己必须等待。

## 非目标

- 不保留文件原文快照作为暂存内容，不提供按快照回滚。
- 不恢复自动三方合并：不相交的外部变更不再静默合并。
- 不承诺拦截「校验之后、写入之前」的外部写入。
- 不为占用设置无活动超时或抢占（租约机制未定，见工单风险项）。
